# ADR-003: Validaciones de negocio en la capa de servicio

## Estado

Aceptado - 2026-06-01

## Contexto

La API recibe datos para crear productos y actualizar stock. Si las validaciones quedan en el controlador, seria mas dificil reutilizar la logica desde otros canales o probarla sin infraestructura HTTP.

## Decision

Las reglas de negocio principales se ubican en `ProductoServiceImpl`: nombre obligatorio, precio mayor a cero y stock no negativo. El controlador se mantiene delgado y delega las operaciones al contrato `ProductoService`.

## Consecuencias

Positivas:

- Las reglas se prueban de forma directa con JUnit 5 y Mockito.
- La API REST queda enfocada en recibir solicitudes y devolver respuestas.
- Un futuro canal distinto a REST podria reutilizar el servicio sin duplicar validaciones.

Negativas:

- Los errores se exponen actualmente como excepciones generales y podrian necesitar un manejador global para respuestas HTTP mas consistentes.
- Si aumentan las reglas, `ProductoServiceImpl` podria crecer demasiado y requerir objetos de validacion dedicados.
