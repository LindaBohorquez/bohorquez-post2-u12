# ADR-001: Arquitectura por capas para el microservicio de productos

## Estado

Aceptado - 2026-06-01

## Contexto

El microservicio gestiona productos mediante una API REST simple. El equipo necesita una estructura facil de entender, probar y mantener para separar las responsabilidades de entrada HTTP, reglas de negocio y persistencia.

## Decision

Se adopta una arquitectura por capas con `controller`, `service`, `repository` y `domain`. Los controladores exponen la API REST y delegan la logica en `ProductoService`. La capa `repository` concentra el acceso a datos con Spring Data JPA. El dominio se mantiene separado de las capas internas de aplicacion para evitar dependencias circulares.

## Consecuencias

Positivas:

- La responsabilidad de cada paquete queda clara.
- Las pruebas unitarias del servicio pueden usar Mockito sin levantar todo el contexto web.
- ArchUnit puede verificar automaticamente las dependencias entre capas.

Negativas:

- No se alcanza el aislamiento completo de una arquitectura hexagonal, porque la entidad `Producto` conserva anotaciones JPA.
- En funcionalidades mas complejas podria ser necesario introducir DTOs, mappers o puertos para reducir acoplamiento.
